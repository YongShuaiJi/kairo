# Runtime Mock 主题设计语言

Runtime Mock 支持三种外观模式：白天、夜晚、跟随系统。白天和夜晚是两套明确的视觉语言；跟随系统不定义第三套颜色，而是根据操作系统偏好自动落到白天或夜晚。

## 白天模式

白天模式用于常规办公环境和长时间配置工作。

- 背景：低饱和浅灰，避免纯白大面积刺眼。
- 内容面板：白色或半透明白色，边框使用浅灰。
- 文字：主文字接近黑色，辅助文字使用 slate 灰阶。
- 强调色：靛蓝用于主操作、选中态和关键路径。
- 状态色：绿色表示成功，琥珀表示等待或注意，红色表示错误或危险。
- 阴影：轻阴影，只用于悬浮层、面板和重要卡片。

## 夜晚模式

夜晚模式用于低光环境、投屏排障和长时间观察。

- 背景：深蓝黑底，不使用纯黑作为主背景。
- 内容面板：深 slate 面板，边框提高可见性但保持克制。
- 文字：主文字使用浅灰，辅助文字降低亮度，避免大面积高亮。
- 强调色：靛蓝提亮，用于选中态、焦点、主按钮和链接。
- 状态色：保留语义，但降低背景饱和度，避免红/绿/黄在暗底上刺眼。
- 阴影：使用深色扩散阴影，弱化浮层边界的硬切割。

## 跟随系统

跟随系统只保存用户选择为 `system`，实际展示由 `prefers-color-scheme` 决定：

- 系统是浅色时应用白天模式。
- 系统是深色时应用夜晚模式。
- 操作系统偏好变化时，控制台自动切换。

## 实现约定

- 主题状态存储在 `localStorage.runtime-mock-theme`，值为 `light`、`dark` 或 `system`。
- HTML 根节点会写入 `data-theme-mode` 和 `data-theme`。
- 白天有效主题类为 `theme-day`，夜晚有效主题类为 `theme-night`。
- 新组件优先使用全局 token：`--background`、`--foreground`、`--surface`、`--border`、`--primary`。
- 现有 Tailwind slate/white 类由全局样式在夜晚模式做兼容覆盖；新增复杂组件应逐步改为 token 驱动，减少硬编码颜色。
