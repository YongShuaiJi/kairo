# 去除发布灰度批次与打通真实流量回放实施方案

## 1. 结论与复杂度

本次改造属于高复杂度结构调整，不能只删除前端“灰度批次”页签。

当前灰度批次已经进入数据库表结构、发布状态机、Agent 命令、执行结果回写、回滚、查询接口、前端资源页和自动化测试。流量回放虽然已有计划、批次、结果等外壳，但执行器尚未真正读取数据集并逐条回放，缺少可证明的真实闭环。

因此采用“先迁移数据模型，再逐层替换，最后端到端验收”的实施方式。

## 2. 发布目标模型

### 2.1 删除的概念

- 发布灰度批次 `rollout_batch`
- 独立发布计划壳 `rollout_plan`
- “发布与灰度”“灰度批次”等产品名称和页面
- 创建发布计划时手工填写批次 JSON
- 以批次作为实例执行、命令和状态推进的中间层

### 2.2 保留的概念

- 发布计划 `operation_plan`
- 发布目标快照 `rollout_target_snapshot`
- 实例执行 `rollout_instance_execution`
- Agent 命令 `agent_command`
- 自动回滚与主动卸载能力

### 2.3 新执行关系

```text
operation_plan
  ├─ rollout_target_snapshot
  └─ rollout_instance_execution
       └─ agent_command
```

DEV、SIT、UAT 默认作用于该应用和环境下全部在线、已分配的实例。PROD 当前也可默认全实例，但数据结构保留未来按实例、标签或比例选择目标的扩展位，不再引入传统“第 N 批”概念。

发布策略统一写入 `operation_plan.strategy_json`，建议结构：

```json
{
  "targetMode": "ALL_ACTIVE_INSTANCES",
  "automaticRollback": true
}
```

## 3. 数据库迁移

新增迁移完成以下工作：

1. 为 `rollout_instance_execution` 增加 `operation_plan_id`。
2. 通过原批次关系回填历史执行记录。
3. 将实例执行唯一约束调整为“发布计划 + 实例”。
4. 将目标快照继续直接关联 `operation_plan`。
5. 删除实例执行的 `rollout_batch_id` 外键和字段。
6. 删除 `rollout_batch`、`rollout_plan`。
7. 为数据集对象引用补充回放读取所需的加密元数据。
8. 对历史录制对象和提取产物回填加密元数据。

迁移必须兼容已有数据，不能依靠清库才能启动。

## 4. 发布后端改造

- 创建发布计划时不再创建批次。
- 计划审批后直接进入待执行/执行中状态。
- 执行器一次性选取目标实例、保存快照并创建实例执行。
- 命令确认直接汇总到发布计划。
- 全部实例成功后计划成功；任一实例失败时按策略回滚。
- 当前允许创建人审批自己的发布。
- 卸载操作按发布计划查找成功实例并发送清除字节码命令。
- API、OpenAPI、查询 DTO 和状态文案删除批次字段。

## 5. 真实流量回放模型

### 5.1 录制

1. 用户选择应用、环境和 Agent 已发现的方法。
2. 平台发送开始录制命令。
3. Agent 拦截真实调用并上传参数、返回值、异常和时间信息。
4. 平台脱敏、加密并写入 MinIO。
5. 停止录制后封存录制批次。

### 5.2 数据集

1. 用户从已完成的录制会话创建数据集版本。
2. 数据集对象引用保存对象地址、校验值、对象类型和加密元数据。
3. 数据集版本不可变并具有可验证的清单。

### 5.3 数据提取

1. 用户从已有数据源和提取模板中选择配置。
2. Worker 执行提取、加密产物并写入 MinIO。
3. 提取成功后生成不可变数据集版本。
4. 前端展示任务、结果、产物和生成的数据集。

### 5.4 回放

1. 回放执行器读取指定数据集版本的真实对象。
2. 解密 JSONL/JSON 数据。
3. 按每条录制事件或提取记录创建一次真实目标调用。
4. HTTP 目标至少支持方法、URL、请求头、请求体来源、期望状态码和响应比较策略。
5. 缺少目标、数据集为空、对象无法解密或目标调用失败时必须明确失败，禁止生成“合成成功”。
6. 保存每次调用、实际响应、差异和汇总状态。

流量回放自己的执行分片可以保留，因为它承担大数据集切片、限流和重试，不属于已删除的发布灰度功能。

## 6. 前端改造

- “发布与灰度”改为“发布管理”。
- 删除“灰度批次”页签和所有批次 JSON。
- 发布计划仅选择应用、环境、规则和版本。
- 规则选项显示“名称（ID）”。
- 增加发布后的卸载/清除字节码入口和执行状态。
- 录制目标改为从 Agent 已发现的方法中选择。
- 数据集来源改为选择已完成的录制会话。
- 数据提取改为选择已有数据源和模板。
- 回放改为选择数据集、回放计划和结构化目标参数。
- 所有状态、动作、字段标题和错误提示使用中文展示；协议枚举值可在后端内部继续使用英文。

## 7. 实施顺序

- [ ] 数据库迁移与发布领域模型调整
- [ ] 发布执行、回写、回滚与卸载调整
- [ ] 发布 API、查询、OpenAPI 和测试调整
- [ ] 发布管理前端调整
- [ ] 数据集对象加密元数据贯通
- [ ] 真实数据集读取与逐条回放
- [ ] 录制、数据集、提取、回放前端选择器和操作流
- [ ] 单元测试、集成测试、静态检查
- [ ] 构建镜像并启动完整容器环境
- [ ] 浏览器端到端验收和问题修复

## 8. 最终验收矩阵

只有以下场景全部通过，才可以声明完成：

1. 真实 Demo 项目通过 Agent 自动注册，页面显示真实项目名、应用名、主机和运行时。
2. Agent 在线，平台能自动发现可操作的类和方法。
3. 浏览器创建规则、校验规则并保存版本。
4. 创建发布计划，创建人完成自审批。
5. 发布作用于目标环境全部在线实例。
6. 调用 Demo 接口，证明发布前后返回效果发生预期变化。
7. 执行卸载，证明字节码恢复且接口返回原始效果。
8. 开始录制，调用真实 Demo 接口，停止录制并看到真实事件数量。
9. 从该录制会话创建数据集，MinIO 中存在真实加密对象。
10. 执行数据提取，生成产物和不可变数据集版本。
11. 使用真实数据集执行流量回放，每条数据产生真实目标调用和比较结果。
12. 页面能够查看录制、数据集、提取、回放全过程的中文状态和错误信息。
13. 后端单元/集成测试、前端测试、构建全部通过。
14. Docker Compose 完整环境启动后，浏览器无控制台错误、无接口 5xx、无伪造成功记录。

如果任一项只能依靠手工插入假数据、合成执行结果或跳过真实 Agent/MinIO/目标接口，则该项不算通过。
