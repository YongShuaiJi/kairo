# Kairo 平台使用手册

Kairo 是面向 Java 应用的运行时故障注入平台。当前版本只聚焦故障注入闭环：在线 Agent 发现目标方法、控制台创建规则、发布到 DEV/SIT/UAT 环境、需要恢复时卸载规则。

## 适用场景

- 验证下游接口异常、超时、返回值异常时业务系统的容错逻辑。
- 在 DEV、SIT、UAT 环境复现难以稳定触发的异常分支。
- 不重新发版，在运行中的 JVM 方法上临时注入返回值或异常。
- 演练发布与恢复流程，确认故障注入可以被快速卸载。

## 核心对象

- 应用：业务应用，例如 `kairo-demo`。
- 环境：固定为 `DEV`、`SIT`、`UAT`。
- Agent：挂载在 Java 进程中的运行时探针，负责上报实例、目标方法，并执行发布/卸载命令。
- 规则：一段 Groovy 脚本，绑定到一个 Java 方法和执行阶段。
- 发布计划：把某个规则版本下发到目标环境的在线实例。
- 卸载记录：对已发布规则执行恢复，清除规则并还原原始字节码。

## 使用流程

1. 登录控制台。
   打开 Web 控制台，使用 Platform Token 登录。Token 只提交给服务端会话，不写入浏览器本地存储。

2. 确认 Agent 在线。
   进入“Agent 管理”，确认目标应用实例状态为已启用或在线。实例详情中应能看到真实应用名和环境，例如 `kairo-demo / SIT`。

3. 创建规则。
   进入“规则中心”，点击创建规则。选择应用、环境和目标方法，填写规则名称，选择执行阶段，然后编写 Groovy 脚本。

4. 校验和试运行。
   保存前先点击“校验”。校验通过后可以用“试运行”验证脚本语法和决策类型。未保存离开页面时，前端会弹窗确认，避免误操作丢失脚本。

5. 保存规则草稿。
   保存后会生成规则版本。规则本身不会立刻影响业务流量，只有发布后才会生效。

6. 创建发布计划。
   进入“发布管理”，选择应用、环境、规则和规则版本，创建发布计划。目标范围默认为当前环境在线实例。

7. 推进发布状态。
   在发布计划详情中按页面按钮推进状态。V1 不要求人工审批，发布状态由平台调度器和 Agent 命令回执推进。

8. 验证业务效果。
   调用目标业务接口，观察规则注入效果。示例 demo 的下单接口是：

   ```bash
   curl -X POST http://127.0.0.1:18082/demo/orders \
     -H 'Content-Type: application/json' \
     -d '{"userId":"u-001","amount":12.34}'
   ```

9. 卸载恢复。
   进入“发布管理”，打开已发布计划，点击卸载。平台会向成功发布的在线 Agent 下发卸载命令，清除规则并恢复目标类原始字节码。

## 当前试用规则

我已经在本地创建了一条草稿规则，可直接用于试发布和卸载流程：

- 规则名称：`SIT 下单接口故障注入试用规则`
- 规则 ID：`rule-96bdae0b-11e7-4bfd-99dd-3a2c8d08b8e0`
- 应用：`kairo-demo`
- 环境：`SIT`
- 目标方法：`com.example.demo.OrderService#createOrder(Lcom/example/demo/CreateOrderRequest;)Lcom/example/demo/Order;`
- 脚本效果：调用前抛出 `IllegalStateException`

发布前，demo 下单接口应返回正常订单；发布后，同一个接口应触发注入异常；卸载后恢复正常。

## 操作注意事项

- 规则发布后会持续生效，直到执行卸载。
- 创建或修改规则页面有未保存内容时，不要直接关闭浏览器；刷新或关闭会触发浏览器原生确认，站内跳转会触发平台确认弹窗。
- 只在 DEV、SIT、UAT 使用故障注入。生产环境能力不在当前简化范围内。
- 优先选择业务服务层方法作为注入目标，不建议选择基础框架、日志、集合、JDK 内部类等高频公共方法。
- 卸载时确保目标 Agent 在线；离线实例需要恢复在线后才能接收卸载命令。
