## 1. 完整兼容矩阵报告（§8 第 1 项）

- **声明**：`CompatibilityMatrixFixture.scenarios()` 枚举 §6 全部 29 个场景。
- **执行（不再以 DOCUMENTED 占位）**：`CompatibilityMatrixRunner` 在当前 JDK 进程内**真实执行**每一个 `automated=true` 场景：
  - JDK Proxy（`Proxy.newProxyInstance`）、CGLIB 子类代理（Byte Buddy 生成 `$$EnhancerByCGLIB$$` 命名子类）、Byte Buddy 代理（`$ByteBuddy$` 命名子类）经 `DefaultProxyTargetAnalyzer` 分类并推荐目标父类；
  - bridge/synthetic/lambda 经 `SyntheticBridgePolicy` 三态决策；
  - Spring Boot 2.x/3.x、Tomcat WebApp 经 `FrameworkLoaderRecognizer` 真实识别；
  - 自定义 ClassLoader、父子同名类经 `LoadedClassRepository.findAllByName` 真实区分；
  - 首次加载（`PendingEnhancementRegistry` + 首次加载观察者即时物化）、retransform、**真实 JVM redefine 漂移检测**（`Instrumentation.redefineClasses` 改变方法体 → 重定义监听器 → reconciler → `isClassDrifted`）、热更新对账，全部在安装了 `ByteBuddyAgent` 的真实 Agent 上执行；
  - premain/agentmain/attach 经 `ByteBuddyAgent.install()`（自附加）验证附加机制。
- **DOCUMENTED 仅留给有意不自动化的场景**：`cl-bootstrap`（JDK/Bootstrap 增强为独立高风险能力）、`module-closed`（运行模块为开放/unnamed 时由 `ModuleDiagnostics` 单测覆盖）。
- **SKIPPED 仅用于本地不可得的外部依赖**：JDK 8/11/17（本地仅 JDK 21）、Spring AOP（需 Spring 在 agent-core 测试类路径）、Kotlin（需 kotlin-compiler），每条 SKIPPED 携带原因与 CI 指针，绝非静默省略。
- **多 JDK harness**：`CompatibilityMatrixHarness` 在当前 JDK 进程内执行，并通过 `KAIRO_MATRIX_JDK_<v>` 环境变量指向的 JDK home 以子进程执行其余 JDK；未提供的 JDK 报 SKIPPED 并指向 CI。`main` 入口以 `id\toutcome\treason` 行输出，供 CI 子进程聚合。
- **本地执行证据（JDK 21）**：`CompatibilityMatrixHarness.main` 输出 `20 passed, 0 failed, 7 skipped, 2 documented (of 29)`；`CompatibilityMatrixHarnessTest`（3 断言：进程内 agent 依赖场景全 PASSED、外部依赖 SKIPPED 带 CI 指针、多 JDK 报告覆盖全部声明 JDK 且当前 JDK 无 FAILED）与 `CompatibilityMatrixTest`（5 断言）全绿。
- **CI**：`.github/workflows/compatibility-matrix.yml` 是真实可运行的工作流（YAML 已通过解析校验），含 `fast-matrix`（JDK 21 全 reactor + 矩阵）、`full-matrix`（JDK 17/21 构建 + 矩阵）、`legacy-jdk-probe`（JDK 8/11，`continue-on-error`，显式说明需 legacy 构建_profile）、`spring-boot-matrix`、`kotlin-matrix`、`frontend`（lint/typecheck/test/build）。

## 2. 父子 ClassLoader 同名类只增强指定目标（§8 第 2 项）

- **机制**：`LoadedClassRepository.resolveMethodTarget(.., allMatch)` / `resolveConstructorTarget(.., allMatch)` 返回全部候选，多于一个且未声明 `allMatch` 时抛 `AmbiguousTargetException`。
- **精确发布**：`ClassSelector` 携带 `classLoaderId` 即精确选择器。
- **Platform**：`EnhancementTargetResolutionService.resolveAndValidate` 的 `case "AMBIGUOUS"` -> `AMBIGUOUS_TARGET`（409）。
- **Agent**：`PlatformCommandPoller.resolveTarget` 捕获 `AmbiguousTargetException` 返回 `status=AMBIGUOUS` + `candidateLoaderIds`。
- **搜索去重**：`TargetDiscoveryService.search` 聚合键加入 `classLoaderId`，同名跨 loader 类呈现为两个独立目标，绝不合并。
- **自动化证据**：`EnhancementLocationPlatformIntegrationTest.callSiteRuleRejectsAmbiguousTarget`；`CompatibilityMatrixHarnessTest` 断言 `cl-parent-child-samename` PASSED（真实编译两个 URLClassLoader 同名类，`findAllByName` 返回 2）。

## 3. 代理类与目标类分别增强的行为与 Diff（§8 第 3 项）

- **机制**：`ProxyTargetAnalyzer.analyze(Class)` 输出 `ProxyAnalysis`（ProxyType、接口/父类、候选方法、推荐目标、影响解释、支持等级）。系统只**推荐**，不擅自跳转（§4.2）。
- **三栏区分（§5）**：`PlatformCommandPoller` 的 `RESOLVE_TARGET` 与 `DISCOVER_TARGETS` 回显 `declaredClassName`（声明类）、`proxyClassName`（代理类，仅代理时）、`actualEnhancedClassName`（实际增强类 = Kairo 织入类）、`proxySuperclass`、`recommendedTargetClass`。Web `TargetClassColumns` 组件渲染三栏并在代理时给出建议切换目标。
- **Diff**：`BytecodeDiffService` 对代理类与目标类分别增强前后字节码做 before/after 比对。
- **自动化证据**：`DefaultProxyTargetAnalyzerTest`；`CompatibilityMatrixHarnessTest` 断言 `proxy-cglib`/`proxy-bytebuddy`/`proxy-jdk` PASSED（真实生成代理子类并验证分类与推荐）。

## 4. 未加载类首次加载后自动应用规则（§8 第 4 项）

- **机制**：`PendingEnhancementRegistry` 按 `ClassSelector` 预注册规则。
- **即时发现（不再仅轮询）**：`ByteBuddyTransformerManager` 在真实首次加载（`classBeingRedefined == null`）时通过 `ClassLoadObserver` 通知 `AgentRuntime.onClassFirstLoaded`；后者**仅**把物化任务提交到清理执行器（非类加载线程），保证 transformer 无重入。`registerPendingRule` 按需开启 `firstLoadObservationEnabled`，无 pending 时类加载热路径零开销。
- **2s 轮询作为兜底**：`pollPendingMatches` 仍周期执行，作为观察者竞态的安全网。
- **物化**：`materializePendingForClass` / `materializeEntry` 解析真实方法、发布 V1.4 规则链、`markResolved` 记录真实 `ClassIdentity`；模糊多匹配未 `allMatch` 时 `markAmbiguous` 拒绝。
- **自动化证据**：`PendingEnhancementRegistryTest`；`KairoAgentIntegrationTest.firstLoadObserverMaterializesPendingRuleImmediately`（注册 pending 后加载全新类，观察者即时物化生效）；`CompatibilityMatrixHarnessTest` 断言 `life-first-load` PASSED。

## 5. 热更新后成功重新增强或明确漂移失败（§8 第 5 项）

- **自动接线（不再仅暴露 API）**：`ByteBuddyTransformerManager` 在重定义（`classBeingRedefined != null`）且 Kairo 有活动目标时通过 `RedefinitionListener` 把捕获的输入字节交给 `AgentRuntime.onClassRedefinition`；后者在清理执行器上 hash + `HotUpdateReconciler.reconcile`，漂移时置 `driftedClasses`、记录 `target.drifted` 事件，并**重新校验调用点指纹**（`revalidateCallSiteRules`）。仅 `Mode.IDLE`（外部重定义）触发，Kairo 自身 retransform/capture 不触发，消除竞态。
- **漂移即失败**：`AgentRuntime.resolveTarget` 在类漂移时返回 `DRIFTED`；`recordAppliedHash`（发布成功）清除漂移标志（重新锚定）。Platform `AgentCommandService.isChainFailureStatus` 将 ACKED 但内层 `TARGET_DRIFTED` 映射为 rollout `FAILED`。
- **自动化证据**：`HotUpdateReconcilerTest`；`AgentCommandChainFailureStatusTest`；`KairoAgentIntegrationTest.realRedefineFlagsDriftAutomatically`（真实 `redefineClasses` 改变方法体 → 自动 `isClassDrifted` + `resolveTarget` 返回 DRIFTED）；`CompatibilityMatrixHarnessTest` 断言 `life-redefine`/`life-hot-update` PASSED。

## 6. ClassLoader 回收的弱引用/堆分析证据（§8 第 6 项）

- **机制**：`ClassLoaderRepository` 以 `WeakReference<ClassLoader>` + `ReferenceQueue` 跟踪；`pollCollected` 触发 `LoaderCleanupListener` 同步删除五处缓存（snapshot/journal/script cache/rule registry/instrumentation registry）。Bootstrap 特殊跟踪，永不回收。
- **自动化证据**：`ClassLoaderRepositoryTest`（`System.gc` 后 `WeakReference` 为 null，证明不 pin loader）。

## 7. V1.4 规则链、精确卸载与共存无回归（§8 第 7 项）

- **保留**：`RuleChainApplier`/`RuleChainCanonicalizer`/fenced apply/精确 `resetAll`/auto-unload RESET_ALL->RESET_CLASS（V38）/共存探针不变。
- **新接入点隔离**：`ClassLoadObserver`、`RedefinitionListener`、`PendingEnhancementRegistry`、`HotUpdateReconciler`、`SyntheticBridgePolicy`、`ModuleDiagnostics` 默认保持 V1.4 语义。
- **回归证据**：全 reactor 绿；`kairo-integration-tests` 87 测试（含 V1.4 规则链 46 + V1.5 新增 3）全绿。

## 14. 仅有的真实外部限制（非计划内延后）

1. **本地仅 JDK 21 可用**（`/usr/libexec/java_home -V` 仅列 21.0.11；无 SDKMAN/Homebrew openjdk）。矩阵 harness 在 JDK 21 进程内执行 20 个场景；JDK 8/11/17 在本地报 SKIPPED，由 CI `compatibility-matrix.yml` 的 `full-matrix`（17/21）与 `legacy-jdk-probe`（8/11）覆盖。
2. **JDK 8/11 需 legacy 构建配置**：Agent 以 `java.version=17` 为基线（Spring Boot 3）。JDK 8/11 需独立的 `java.version=8/11` + Spring Boot 2.x 构建_profile；CI `legacy-jdk-probe` 以 `continue-on-error` 显式记录该要求，而非静默占位。
3. **Spring AOP / Kotlin 真实 fixture 不在 agent-core 测试类路径**：矩阵将这两类报 SKIPPED 并指向 CI 的 `spring-boot-matrix`/`kotlin-matrix` 作业；agent-core 矩阵以 `FrameworkLoaderRecognizer` 真实识别 Spring/Tomcat loader、以 `method-synthetic` 覆盖 Kotlin 默认参数的 JVM 形态。
4. **未提交**：全部改动为工作区未提交状态，按要求不 commit。
