# V1.2 验收记录

结论：**ACCEPTED**。验收基线为 `V1.2` 分支（phase 1–5 完整实现，未提交）。

V1.2 把脚本能力从硬编码黑名单升级为 `SAFE / EXTENDED / UNRESTRICTED` 三档可审计、可试用、可
过期恢复的完整生命周期。phase 5（step 7）补齐了 Agent 侧真实 JVM 命令处理、Web 控制台、端到端
集成与可观测性，并交付本验收证据。

## 契约与功能证据

- 三档能力档位与有效策略 `min(平台上限, 应用上限, 请求档位)` 在 `kairo-api.CapabilityProfile` 冻结，
  Platform 计算并下发、Agent 二次校验（§2.1）；
- `ScriptSecurityPolicy` 三实现 + 共享大小上限；`ScriptCompilationContext` 携带 profile / revision /
  目标 ClassLoader / allow-list；编译缓存键含 profile + targetClassLoaderId + policyRevision +
  groovyVersion，弱引用目标 ClassLoader（§2.2）；
- `RuleDispatcher` 超时 / 线程数 / 失败阈值配置化；超时取消 Future、熔断规则、记录未退出任务，
  fail-open 区分 timeout / saturation / failed（§2.3）；
- Agent `ScriptSessionManager` 本地 TTL + 命中上限 + 紧急停用索引；状态机
  `CREATED/VALIDATED/APPLIED/EXPIRED/REVERTED/FAILED`；promote 不扩权（§2.4）；
- Platform `ScriptSessionService` 计算最终档位、创建试用会话、下发命令、过期补偿、提升正式规则；
  乐观锁 + 幂等键；脚本源码只存于内存 exchange，持久层仅存 hash（§3.5）；
- V36 迁移新增 `script_capability_policy` / `script_session` / `script_session_event` 三表，PLATFORM 行
  seed 为 `UNRESTRICTED`；
- API（§3.6）：`GET/PUT /api/v1/apps/{appId}/script-policy`、`POST /api/v1/scripts/compile`、
  `POST /api/v1/script-sessions`、`GET /api/v1/script-sessions`、`GET /{id}`、`POST /{id}/validate|apply|promote`、
  `DELETE /{id}`、`GET /{id}/events`；
- Web 控制台（`/script-sessions`）展示档位、真实权限、TTL、目标实例、事件审计与安全说明。

## 使用目标应用私有 DTO 的真实编译 / 执行

`ScriptCapabilityIntegrationTest.classLoaderIsolatedBusinessDtoCompilesAndExecutes`：把 `biz.BizScore`
编译进独立 `URLClassLoader`（对 Agent ClassLoader 不可见），以 UNRESTRICTED 试用会话定位其 `score(I)I`，
脚本引用 `new biz.BizScore()` 与 `biz.BizScore.bonus()` 并在真实 JVM 上执行，断言 `Class.forName("biz.BizScore",
false, agentLoader)` 抛 `ClassNotFoundException`——证明脚本只可能被编译为目标方法所属 ClassLoader。

## Platform 断开后的 TTL 自动卸载

`ScriptCapabilityIntegrationTest.trialSessionExpiresWithoutPlatformConnectivity`：集成运行时**没有任何
Platform 轮询器**，试用会话仍按本地截止时间过期、移除试用规则、恢复原方法行为。Agent 持有本地 `Clock`
与 deadline，`expireDue()` 由 cleanup executor 每秒扫描，每次访问懒过期——在线 / 离线 / 客户端断开
三场景归约为“本地时钟到了就过期”。Platform 侧 `expireSessions` 作为纵深防御，best-effort enqueue
revert，Agent 不在时 enqueue 抛错被吞（`ScriptSessionLifecycleIntegrationTest` 覆盖 agent 不在仍 EXPIRED）。

## 超时后 fail-open、熔断与未退出任务诊断

`KairoAgentIntegrationTest.slowScriptTimesOutCircuitBreaksAndFailsOpen`：3s sleep 脚本（UNRESTRICTED）
触发 1s 首次执行超时 -> `execution.cancel(true)` -> `CompiledRule.circuitBreakReason() == TIMEOUT` ->
`unfinishedTaskCount() >= 1` -> fail-open 原方法返回 14。`RuleDispatcherTest` 覆盖 timeout / saturation
（`RejectedExecutionException`）/ 连续异常三种 fail-open，并断言熔断后后续命中被跳过。脚本内部异常、
校验异常与执行器拒绝均 fail-open，不破坏原方法（§7）。

## 旧 V1.0 规则兼容

`ScriptCapabilityIntegrationTest.legacyRuleWithoutProfileDefaultsToSafe` 与
`AgentScriptCompilerFactoryTest.legacyRuleWithoutProfileDefaultsToSafe`：不带 `capabilityProfile` /
`policyRevision` 的旧规则自动按 SAFE 处理——普通脚本编译执行，`java.io.File` 被拒绝；`MockRule.Builder`
默认 `capabilityProfile = SAFE`。旧 JSON 映射无需改动。

## API、审计与数据库迁移

- **API**：见上文契约清单；403（无 `RULE_MANAGE`）/404/400/409 经 `PlatformExceptionHandler`；script source
  不入 `agent_command.payload_json`（`ScriptSessionLifecycleIntegrationTest.compileDispatchesCommandAndReturnsAgentResult`
  断言 payload 不含脚本明文）。
- **审计**：每次状态变化写 `script_session_event` 与统一审计事件；`script_session.create` 记录
  `requestedProfile` / `effectiveProfile` / `platformMaxProfile` / `applicationMaxProfile` /
  `decisionSource = "min(platform, application, requested)"`（§2.1）；`script_session.expire` / `failed` 同理。
  Web 详情页“事件历史”直接展示。
- **数据库**：`V36__script_capabilities.sql` 三表，全部可变状态用乐观锁（`revision` / `version`）+ 幂等键；
  PLATFORM 行 seed `UNRESTRICTED`；H2 PostgreSQL mode 测试通过。

## 端到端命令闭环（phase 5）

`PlatformScriptCommandTest`（9 项）经 `PlatformCommandPoller.execute()` 驱动全部六类 `SCRIPT_*` 命令
（CREATE / VALIDATE / APPLY / PROMOTE / REVERT / COMPILE）对抗真实 JVM：试用规则拦截 live 方法、promote
留正式规则、revert 幂等、compile 成功返回 `groovy-<version>`、失败返回结构化 `ScriptDiagnostic`、
SAFE 拒绝 `java.io.File`（`FORBIDDEN_SCRIPT`）、UNRESTRICTED 放行反射、未知 ClassLoader 报清晰诊断。

## 完成判定（§7）

三种档位语义稳定（矩阵双覆盖）；完整权限能实际执行（UNRESTRICTED IO/反射/线程 + 私有 DTO 真实编译执行）；
任何档位异常都 fail-open 不破坏原方法（timeout / saturation / 脚本异常均覆盖）；临时会话在控制面失联时
仍能自动失效（本地 TTL 独立于 Platform）。**判定完成。**

## 已知边界（留待后续）

- 提升为正式规则后，Platform 尚未把正式规则写入 `rule_version` 表做对账恢复（当前以 `formal_rule_id =
  sessionId` 在 `script_session` 行标记；Agent 侧重启后正式规则由 Platform 对账恢复属后续工作）。
- EXTENDED 的 allow-list 目前仅在编译上下文层配置（`ScriptCompilationContext.allowedPackages/Classes`），
  未通过 Platform 策略持久化下发到会话；会话路径下 EXTENDED 等价于 SAFE 敏感硬底 + 基线 allow-list。
