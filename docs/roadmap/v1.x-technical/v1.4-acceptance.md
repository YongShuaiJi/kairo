# V1.4 验收记录

结论：**ACCEPTED**。验收基线为 `V1.4` 分支（实现未提交）。

V1.4 把规则执行从 V1.2 的“首个非 PROCEED 决策即返回”升级为可版本化、可解释、可冲突检测的
正式规则链：冻结排序与传播语义、不可变链快照、确定执行状态机、事务式 apply、expected/desired
revision fencing、精确卸载与其他 Agent 共存。

## 契约与功能证据

- **排序与 hash（§2.1）**：规范化键 `priority DESC, createdAt ASC, ruleId ASC` 与 SHA-256 canonical JSON
  由 `kairo-api.RuleChainCanonicalizer` 实现，Platform 与 Agent 共用同一算法（纯 JDK，无第三方依赖）。
  `RuleChainCanonicalizerTest`（6）覆盖排序、顺序无关 hash、内容/目标/调用点变化改变 hash、1000 次循环
  hash 一致。
- **数据传递（§2.2）**：`InvocationState` 同时保留 original/current（参数、结果、异常）与 `OutcomeState`；
  `InvocationContext` 暴露 `originalArguments/originalResult/originalThrowable/outcomeState`，脚本必须显式
  读取。`RuleChainDispatcherTest` 覆盖 BEFORE 参数逐条修改、RETURN 逐条替换并继续（后续规则观察到替换值）、
  THROWS 异常替换与恢复为返回值、FINALLY observe-only。
- **传播控制（§2.3）**：`PropagationMode`（CONTINUE/TERMINATE/PROCEED_ORIGINAL/FAIL_OPEN/FAIL_CLOSED）+
  `RuleChainDecision`。`MockDecision` 旧 `proceed/returnValue/throwException` 在 `RuleChainDecision.from`
  固定映射到 CONTINUE/TERMINATE；新增 `replaceReturnValue/replaceThrowable/proceedOriginal/failOpen/failClosed`
  工厂与 `MockApi` 同名方法。`RuleChainDecisionTest`（8）覆盖映射。FAIL_CLOSED 非默认能力，dispatcher 无
  应用策略时降级为 FAIL_OPEN；**校验失败**（如 null 赋给 int）走 `FAIL_OPEN_BODY`（保持原业务行为，与 V1.2
  一致），与脚本显式 FAIL_OPEN（继续链）区分。
- **冲突（§2.4）**：`ConflictAnalyzer` 静态识别多无条件终止、不可达、互斥组、独占调用点替换、能力超限、
  调用点指纹漂移；业务条件不可静态判定时标 `POTENTIAL`。`ConflictAnalyzerTest`（8）覆盖各 conflict kind。
- **期望/实际状态（§3.1/§3.2）**：`RuleChainSpec`（desired：chainId/revision/canonicalHash/entries/
  transformationRevision/ACTIVE|EMPTY）+ `RuleChainSnapshot`（actual：appliedRevision/hash/compiledRules/
  transformationRevision/hash/applyTime/degradedReason），不可变，原子引用替换。业务线程只读快照。
- **命令 fencing（§3.3）**：`ApplyChainRequest` 携带 commandId/idempotencyKey/expectedRevision/
  desiredSpec/rules/target/deadline。`RuleChainApplier` 校验 expected revision 匹配 actual，否则
  `STALE_COMMAND`；重复 idempotency key 返回 `IDEMPOTENT_REPLAY`。`RuleChainIntegrationTest` 覆盖。

## Agent 精确 apply 与卸载（§4.2）

- `AgentRuntime.applyRuleChain` 收敛 publish/remove 为完整链 apply：**先编译全部期望链再转换**（任一编译
  失败不修改当前快照）→ 冲突分析 → footprint 变化时才 retransform → V1.1 实际字节码结果校验 → 原子 CAS
  替换运行快照。
- **仅内容变化不重转换**：`contentOnlyChangeSwapsSnapshotWithoutRetransform` 断言相同 footprint 下
  `retransformCount` 不变，仅替换快照。
- **精确卸载**：卸载 = 期望链 `EMPTY`，重新生成剩余 Kairo 计划按类 retransform，非 `RESET_ALL`。
  `unloadRemovesRuleAndRestoresBehaviour` 验证行为还原；`preciseUnloadOfMiddleRuleKeepsOthersEffective`
  验证卸载中间规则后其他规则仍生效（10+1+100=111）。

## 自动卸载不再使用 RESET_ALL（§4.3 / §7 代码证据）

- `AgentCommandService.startAutomaticUnload` 由 `RESET_ALL` 改造为 `RESET_CLASS`（精确按类回滚），
  解析失败规则的 target class 并下发 RESET_CLASS，仅 retransform 受影响类。`grep RESET_ALL` 确认
  platform/agent-server 主代码仅剩 `PlatformCommandPoller` 的命令分支（接收方）与 web 按钮触发，
  自动卸载路径不再 enqueue RESET_ALL。
- `AgentRuntime.resetAll` 不再 `transformerManager.close()+install()`（粗粒度 transformer.reset），
  改为清空 Kairo 期望链 + 按类 retransform + `recordRecovery`，保留 transformer 注册与其他 Agent advice。
- V38 迁移新增 `rule_chain_desired_state/instance_state/operation/operation_target` 表与
  `agent_command` 的 expected/desired revision + result hash 列。
- `RuleChainStateService` 提供 desired state 的 CAS（revision+version 乐观锁）+ instance ack + reconcile。
  `RuleChainStateServiceTest`（5）覆盖 CAS 推进、stale expected 拒绝、重复 idempotent 拒绝、reconcile
  behind/in-sync。

## 共存（§4.4 / §7）

- `ForeignTransformerProbe` + `ByteBuddyTransformerManager.coexistenceUnsafe`：非幂等 foreign transformer
  在 Kairo 之前时返回 `COEXISTENCE_UNSAFE`。`RuleChainIntegrationTest.coexistenceUnsafeWhenForeignTransformerAheadIsNotIdempotent`
  断言 apply 返回 COEXISTENCE_UNSAFE。
- `foreignMarkerSurvivesKairoUnload`：安装 `AttributeAddingTransformer`（foreign 标记），apply+unload 后
  实际字节码仍包含 `V14ForeignMarker`——证明 Kairo retransform 只声明自己的 visitor，不移除未知 advice。
- retransform 使用 V1.1 本次转换 input 作为基线（`InputCaptureTransformer`，不缓存强写启动 bytes）。

## 测试矩阵（§6）与验收证据（§7）

- **组合**：参数逐条修改、返回逐条替换、异常替换、异常恢复、FINALLY → `RuleChainDispatcherTest`。
- **传播**：continue/terminate/fail-open/proceed-original → `RuleChainDispatcherTest`。
- **并发**：调用过程中切链 → `invocationUsesFrozenSnapshotDespiteMidInvocationPublish`（一快照 per invocation）。
- **幂等**：重复、乱序、旧命令晚到 → `RuleChainIntegrationTest`（duplicateIdempotencyKeyReplaysResult、
  outOfOrderLateCommandIsStale、staleCommandIsRejected）。
- **恢复**：局部卸载、最后一条卸载、中间规则卸载 → `RuleChainIntegrationTest`。
- **共存**：foreign marker 前后 + COEXISTENCE_UNSAFE → `RuleChainIntegrationTest`。
- **压力**：1000 次组合/局部卸载，最终 hash 一致 → `thousandCyclesOfPartialUnloadProduceStableHash`
  （1000 次 partial-unload + re-apply，hash 每轮回到原值，最终行为 21）。
- **fencing 日志/API**：`RuleChainStateServiceTest`（platform CAS 拒绝 stale/duplicate）+
  `RuleChainIntegrationTest`（agent STALE_COMMAND/IDEMPOTENT_REPLAY）。

## 完成判定（§8）

Platform 期望链（`rule_chain_desired_state` revision/hash）、Agent 实际链（`RuleChainSnapshot`）与 JVM
实际字节码（V1.1 transformation revision/hash）三者可通过 revision/hash 对账（`RuleChainStateService.reconcile`
+ `RuleChainApplier.reconcile`）；任意规则可精确卸载（中间规则卸载后其他仍生效）；乱序操作不破坏新状态
（fencing 拒绝 stale/duplicate）；共存矩阵中其他 Agent 的标记被保留。**判定完成。**
