# V1.6 验收证据：API First 与 AI First

对应方案 `docs/roadmap/v1.x-technical/v1.6-api-ai-first.md`，最终交付分支为 `V1.6`。
本版本冻结公开 API V1，使 Web、CLI、SDK、MCP 成为同一 Platform API 的客户端，并提供
带 TTL、可观察、可撤销的 AI 操作会话。证据全部来自真实测试运行（无伪造）。

## 0. 实施顺序与覆盖（对应 §7）

1. **冻结契约**（kairo-api + platform `api.dto`）：错误模型 v2、`Page`/`PageRequest` 分页、
   `Operation`/`OperationEvent`、写操作协议（`RiskLevel`/`ImpactSummary`/`WriteMeta`/`PreviewResult`）、
   `AutomationSession`/`AutomationSessionResource`/`EnhancementContextBundle`/`ScriptApiSurface`。
   见 `kairo-api/src/main/java/com/example/kairo/api/{error,paging,operation,write,automation}`。
   契约测试 `V16ApiFirstContractTest`（11）。
2. **OpenAPI 契约**：springdoc 生成 `/v3/api-docs`；`OpenApiContractTest`（5）守护路径/schema/deprecated/typed DTO，`WebOpenApiCompletenessTest` 守护 Web 注册表 ⊆ live OpenAPI。
3. **强类型化核心 DTO**：建立 `platform.api.dto` 包；核心写路径改为 typed DTO：
   `POST /instances`(`CreateInstanceRequest`)、`POST /fencing-tokens`(`IssueFencingTokenRequest`)、
   `POST /sidecars`(`CreateSidecarRequest`)、`POST /agents`(`CreateAgentRequest`)、
   `POST /operation-plans`(`CreateOperationPlanRequest`)、`POST /rules`(`CreateRuleRequest`)、
   `POST /rules/{id}/versions`(`CreateRuleVersionRequest`)、`POST /rules/preview`(`RulePreviewRequest`)。
   规则版本载荷（targets/script/matcher）已完整强类型化（`RuleTargetDto`/`RuleTargetMatcherDto`/
   `RuleScriptDto`/`RuleMatcherDto`，含 `protocol`/`className`/`classLoaderId`/`descriptor`/`phase`）。
   控制器 DTO->Map 传入既有 service（边界不变、向后兼容，既有控制器集成测试全绿）。OpenAPI 发布具体 schema，
   `OpenApiContractTest.coreWritePathPublishesTypedRequestSchema` 守护全部 schema（5 条核心写路径 + 规则/预览载荷）。
4. **统一 Operation + AutomationSession**：V40 迁移（`operation`/`operation_event`/
   `automation_session`/`automation_session_resource` + 扩展 `platform_access_token` 的
   scope/source/max_sessions）。`OperationService`、`AutomationSessionService`、token scope 收窄、
   会话上限、TTL 清理（接入 `PlatformMaintenanceService`）。**Operation 收敛**：`PlatformController`
   在 operation-plan transition(unload) 即发布(回滚)成功后，best-effort 记录统一 `Operation`
   （RULE_PUBLISH / RULE_ROLLBACK，risk=HIGH），使发布/回滚长任务可经 `/operations` 查询。
5. **Web 迁移 + API 完整性审计**：`lib/api/error.ts`（基于 code 的错误处理）、`lib/api/automation.ts`、
   `lib/rules/assembly.ts`（过渡性集中装配）、`api-completeness-audit.md`。
6. **CLI + SDK**：`kairo-sdk`（`KairoClient` + `KairoClientTest` 4）、`kairo-cli`（`KairoCli` + 4）。
7. **MCP + AI E2E**：`kairo-mcp`（`KairoMcpServer` + 5，preview-first、apply 必带 previewToken）；
   `V16AiE2eAcceptanceTest`（2）。

## 1. Web 请求与 OpenAPI operation 100% 对照报告（§9 第 1 项 / §6）

**自动校验，非手工清单**。Web 侧 `kairo-platform-web/tests/web-openapi-completeness.test.ts`
扫描 `lib/api`、`components`、`app` 的真实源码，提取每个 BFF 发起的 Platform 请求（platformFetch /
listResource / 指向 `/api/platform` 或 `/api/v1` 的 fetch），按结构化模板（`${...}`→`{}`，`{param}` 匹配任意段）
证明每个调用点都被权威注册表 `lib/api/paths.ts` 覆盖。Platform 侧 `WebOpenApiCompletenessTest`
读取 `paths.ts` 并证明其中每个 operation 都存在于 live `/v3/api-docs`（method + path）。两侧合起来：
**Web 发起的每个请求都映射到一个真实 OpenAPI operation**，新增 Web 请求未登记或 Platform 移除 Web 依赖的
operation 均构建失败。鉴权/幂等/结构化错误/审计覆盖见 `api-completeness-audit.md`。OpenAPI 由 springdoc
从控制器与 DTO 生成（`OpenApiConfig`），`/v3/api-docs` 公开可发现（认证过滤器放行，便于 AI/SDK 发现）。

## 6. AI 自动修正一次结构化脚本错误并完成临时增强（§9 第 6 项 / §8 AI E2E）

`V16AiE2eAcceptanceTest`（2）：仅凭 Token + 意图完成
create session -> resolve-targets（返回 `EnhancementContextBundle`，含 scriptApiSurface 的
schema/examples/diagnosticsFormat，且 `sizeBytes <= 256KB`）-> validate 故意写错的脚本
（`def x =`，返回 `{valid:false, diagnostics:[{code,severity,...}]}`，**按 code/severity 分支而非解析 message**）
-> AI 依据结构化诊断"修正"脚本 -> validate 通过（`valid:true`）-> 一键 revert（`REVERTED`）。
HTTP 与服务两条路径均覆盖。

`V16AiFullLifecycleE2eTest`（1）：**一条非拼装（non-stitched）的 Token + 意图端到端**，驱动完整生命周期：
用 AI scoped token（RULE_MANAGE）经真实 HTTP 创建会话 -> resolve-targets（结构化上下文包）->
validate 写错脚本（结构化诊断）-> AI 按 code 修正 -> re-validate 通过 -> **preview**（真实 Agent 命令通道
RESOLVE_TARGET ack MATCHED，返回 previewToken/revision/risk）-> **trial**（create+validate+apply，经真实
Agent 命令通道派发，**模拟 Agent ack**，APPLIED）-> **observe**（`/automation-sessions/{id}/events` 含
AUTOMATION_TRIAL operation；`/operations?resourceType=script-session` 返回该 operation）->
**promote**（PROMOTE ack，formalRuleId）-> **一键 revert**（REVERTED，revertedCount>0）。服务边界无任何 mock，
仅模拟 Agent ack（无真实 Agent 进程，故不在此断言真实方法行为变更）。`V16AiTrialRealJvmTest`（1）以同样方式
（模拟 ack）单独覆盖 trial+revert 的平台侧状态机与资源簿记。

**真实 Agent + 真实插桩的行为变更与回退**（Codex 验收安全复核要求）：`V16RealAgentAiLifecycleTest`（1）在同一
JVM 内安装 ByteBuddy 插桩、启动真实 `AgentRuntime` + `PlatformCommandPoller`，将平台派发的每条 `SCRIPT_SESSION_*`
命令交给 `poller.execute` 在真实 JVM 上执行（编译 Groovy 脚本 + ByteBuddy 重定义目标方法）后回 ack，驱动
`AutomationSessionService.trial`（create+validate+apply）与 `revert`。断言目标方法 `RealAgentTrialTarget.compute(int)`
的行为**真实变更**：`compute(7)` 基线 14 -> apply 后 42 -> revert 后 14。即通过真实 Agent 与插桩贯通 AI 生命周期，
而非仅模拟 ack。

## 7. AI 客户端中断后 Agent 按 TTL 清理（§9 第 7 项 / §4.1）

`AutomationSessionService.expireSessions()`（接入 `PlatformMaintenanceService.expireAutomationSessionsScheduled`
与 `runOnce`）扫描 `status in (CREATED,ACTIVE) and deadline_millis < now` 的会话，best-effort revert
其可逆资源并标记 `EXPIRED`。`V16AutomationSessionIntegrationTest.ttlExpiryRevertsAndExpiresSession`
将会话 deadline 置为过去，触发清理后断言 `status=EXPIRED`；
`revertOnExpiredSessionReturns409` 断言终态会话再 revert 返回 `AUTOMATION_SESSION_TERMINAL`(409)。
（注：真实"客户端断开"由 TTL 绝对截止时间兜底，无需客户端在线。）

## 8. 所有写 API 的幂等与乐观锁测试（§9 第 8 项 / §8）

- 幂等（数据库安全预约协议，V1.6 验收安全）：`IdempotencyFilter` 不再"先查后执行后插"，改为原子预约/执行中/完成
  协议（V41 迁移为 `idempotency_record` 增加 `status` 与 `lease_expires_at`）：(1) **预约** —— 原子 `INSERT`
  一条 `IN_PROGRESS` 行（主键冲突即他节点持有），持有者执行请求；(2) **完成** —— 2xx-4xx 响应缓存为
  `COMPLETED` 供回放，5xx 或持有者失败则**删除**预约（5xx 绝不缓存为成功）；(3) **等待回放** —— 同 key 同请求
  （同 actor + 同 hash）的并发等待者轮询直到持有者完成，回放缓存结果而不重执行；(4) **冲突** —— 同 key 异请求
  返回 `IDEMPOTENCY_KEY_CONFLICT`(409)；(5) **恢复** —— 持有者租约过期（owner 死亡）时，同请求等待者回收预约并
  重新执行。`V16WriteApiIdempotencyOptimisticLockTest`（5）覆盖单线程回放/冲突；`V16ConcurrencyAcceptanceTest`（5）
  在真实嵌入式服务器（`RANDOM_PORT` + `TestRestTemplate`）上以 `CountDownLatch` 同时释放多线程，证明：**并发同 key
  同请求恰好执行一次**（所有响应同 sessionId 且仅一行）、**并发同 key 异请求冲突且无双执行**、**5xx 释放后重试重新执行**
  （5xx 不缓存）、**过期租约被回收并重新执行**（新 sessionId，行回到 COMPLETED）；既有
  `PlatformLocalTokenIntegrationTest`/`PlatformWebContractIntegrationTest` 覆盖过滤器的 UTF-8 错误与常规写；
  `OperationServiceIntegrationTest.idempotencyKeyDeduplicatesOperation` 验证 Operation 按 key 去重。
- 幂等（第二复核：持有者令牌围栏 + 租约心跳 + 复用 + Correlation-Id，V1.6 验收安全）：V41 迁移为
  `idempotency_record` 增加唯一 `owner_token` 围栏令牌；预约时盖印，`completeRecord`/`deleteReservation`/`renewLease`
  均要求 `ownerToken` 匹配，`reclaimReservation` 把 `owner_token` 原子改为新值，故 **stale owner 回收后无法 complete/delete
  新 owner 的行**。持有者执行期间后台线程按 `ownerToken` 续约租约（`renewLease`，时序可配置以加速测试），故
  **存活的长请求永不被回收**；等待窗口耗尽而租约仍存活时返回 `409 IDEMPOTENCY_KEY_IN_PROGRESS`（不回收存活 owner，无双执行）。
  过 `expires_at` TTL 的行被原子 `deleteExpired` 删除，主键可复用而非永久冲突。冲突错误回传**真实 `X-Correlation-Id` 头**
  （非 Idempotency-Key）。`V16IdempotencyFencingTest`（3）证明 stale owner 围栏、慢存活 owner 不被回收而等待者回放、
  超窗口存活 owner 返回 `IDEMPOTENCY_KEY_IN_PROGRESS`；`V16ConcurrencyAcceptanceTest`（7）增补过期行复用与 Correlation-Id 回传。
  **分布式保证边界（诚实范围）**：恰好一次执行在**围栏预约状态 + 与处理者同一 Platform/数据库事务**的边界内成立；对该边界
  **之外**的副作用（如已发出的邮件、外部 HTTP 调用），若处理者在完成前崩溃，被恢复的 owner 会重新执行、该副作用**可能被观察到两次**
  -- 这无法在不引入事务性副作用协调器的前提下消除。`ownerToken` 围栏保证 stale owner 永不能**破坏**预约状态，但无法撤销已发生的副作用；
  对此不能容忍的调用方须以事务性或可幂等消费的方式执行外部副作用。
- 乐观锁：`V16WriteApiIdempotencyOptimisticLockTest.automationSessionOptimisticLockRejectsStaleVersion`
  （stale expectedVersion -> 0 行，会话仍 CREATED）；
  `V16OperationIntegrationTest.optimisticLockRejectsStaleTransition`（stale expectedVersion -> 0 行）；
  既有 `ScriptCapabilityPolicyIntegrationTest`（expectedRevision 99 -> 409）、
  `ScriptSessionLifecycleIntegrationTest`（状态冲突 409）、`PlatformControllerIntegrationTest`
  （operation-plan transition expectedVersion -> 409）。即每个版本化写 API 均有乐观锁守护。
- 权限矩阵（fail-closed，V1.6 验收安全）：`TokenScope` 三态模型 -- `null` 继承主体全能力、空集 `[]` 授予**零**
  能力、非空集收窄；`maxSessions` 为 `null` 或正整数，非正一律拒绝（永不静默视为无限）。`AccessTokenService` 在签发与
  认证两处 fail-closed：签发时非数组/含非字符串的 `scope` 或非正/小数/非数值的 `maxSessions` 返回结构化
  `INVALID_TOKEN_SCOPE`/`INVALID_TOKEN_MAX_SESSIONS`(400, VALIDATION)；认证时损坏的 `scope_json`（非 JSON/非数组/
  含非字符串）或非正/非整数 `max_sessions` 返回 `TOKEN_SCOPE_INVALID`/`TOKEN_MAX_SESSIONS_INVALID`(401, AUTHENTICATION)，
  损坏行永不放宽为主体全能力。`V16TokenScopeIntegrationTest`（10）覆盖 scoped token 越权 `TOKEN_SCOPE_DENIED`(403,
  category=AUTHORIZATION, suggestedActions)、空 scope 零能力、null scope 继承、AI scoped token 可建会话、
  `maxSessions` 顺序上限 -> `AUTOMATION_SESSION_LIMIT_EXCEEDED`(409)，以及上述签发/认证 fail-closed 用例。
- 能力协商：`AgentProtocolNegotiationTest`（2）+ `PlatformScriptCommandTest.unsupportedScriptActionIsRejected`
  覆盖 Agent 注册 protocolVersions+capabilities、未广告命令返回 `CAPABILITY_NOT_SUPPORTED`。

## 11. 完成判定（§10）

- Web 不再拥有私有业务能力：所有数据经正式 API client（`lib/api/*`），BFF 仅代理；规则装配由服务端
  `POST /api/v1/rules/preview`（`RulePreviewService`）集中拥有，前端无 `assembly.ts` 拼装、无状态推断、
  无错误字符串判断；错误按 code 分支；Web↔OpenAPI 对照由 `tests/web-openapi-completeness.test.ts`
