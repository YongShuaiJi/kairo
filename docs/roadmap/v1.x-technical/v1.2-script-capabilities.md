# V1.2 技术改造方案：脚本能力全面开放

## 1. 目标与当前差距

当前 `GroovyScriptSecurityPolicy` 使用硬编码黑名单、AST 限制和资源上限；`AgentRuntime` 以 Agent 自身
ClassLoader 创建单一 `GroovyScriptCompiler`。这不支持应用级能力策略，也无法保证脚本编译、试用和
正式运行使用目标方法所属的 ClassLoader。

本版本引入 `SAFE`、`EXTENDED`、`UNRESTRICTED` 三种能力档位，并建立可审计、可试用、可过期恢复
的完整脚本生命周期。

## 2. 技术决策

### 2.1 权限模型

最终有效档位为：

`min(平台允许上限, 应用允许上限, 规则请求档位)`。

档位顺序为 `SAFE < EXTENDED < UNRESTRICTED`。Agent 必须验证 Platform 下发的最终档位，不能只相信
Web。策略更新携带版本和哈希，审计记录请求档位、最终档位和决策来源。

### 2.2 编译器隔离

- `ScriptCompilerFactory` 按 `CapabilityProfile + targetClassLoaderId + policyRevision` 创建编译上下文。
- 编译缓存键包含脚本哈希、Groovy 版本、档位、目标 ClassLoader 和策略 revision。
- 缓存只弱关联目标 ClassLoader；ClassLoader 回收时缓存必须可清理。
- Agent 自身 Groovy 依赖保持在隔离 ClassLoader，业务类通过受控父/委派策略可见。

### 2.3 超时语义

保留 `RuleDispatcher` 当前有界执行器与 fail-open 思路，但修正产品承诺：

- 超时后取消 Future、锁定或熔断规则并阻止后续命中；
- 记录仍未退出的执行任务；
- 不承诺安全强杀任意 Java 线程；
- `UNRESTRICTED` 脚本若创建自己的线程或阻塞 native IO，只能通过隔离、告警和规则停用治理。

### 2.4 临时试用

真实 JVM 试用不是绕过发布系统的隐藏接口，而是正式资源 `ScriptSession`：

- 创建时必须指定 agent、target、profile、TTL 和调用者；
- 状态为 `CREATED/VALIDATED/APPLIED/EXPIRED/REVERTED/FAILED`；
- 默认仅单实例、低命中上限、短 TTL；
- Agent 独立保存截止时间，Platform 断开不影响过期；
- 可提升为正式规则，但不能静默延长权限或作用范围。

## 3. 模块改造

### 3.1 `kairo-api`

新增：

- `CapabilityProfile`；
- `ScriptPolicyRevision`；
- `ScriptCompilationRequest/Result`；
- `ScriptSessionSpec/Status/Result`；
- 结构化 `ScriptDiagnostic`，包含阶段、行列、错误码、ClassLoader 和修复建议。

`MockRule` 增加 profile、policy revision、连续失败阈值和试用来源；保持旧 JSON 默认映射为 `SAFE`。

### 3.2 `kairo-groovy`

- 把 `GroovyScriptSecurityPolicy` 重构为 `ScriptSecurityPolicy` 策略接口。
- `SafeScriptPolicy` 兼容当前限制。
- `ExtendedScriptPolicy` 使用显式允许列表和可配置包/类集合。
- `UnrestrictedScriptPolicy` 不安装安全 AST 黑名单，但仍执行脚本大小、编译产物大小和审计检查。
- `GroovyScriptCompiler` 接收显式编译上下文，不在构造器中固定唯一 ClassLoader。
- 编译结果记录脚本哈希、档位、策略 revision、编译器版本和目标 ClassLoader ID。

### 3.3 `kairo-core`

- `CompiledRule` 增加连续失败、熔断状态、最近耗时和未退出任务计数。
- `RuleDispatcher` 的超时、首次执行超时、线程数和失败阈值改为配置而不是硬编码常量。
- 熔断状态从“脚本报错”中区分出来，并写入运行事件。
- 保证脚本内部异常、校验异常和执行器拒绝均 fail-open。

### 3.4 `kairo-agent-core`

- 根据目标方法 `ClassIdentity` 创建编译上下文。
- 管理脚本编译缓存和 ClassLoader 生命周期。
- 增加本地 TTL 调度、会话恢复和紧急停用索引。
- Agent 重启后，临时会话默认不恢复；正式规则由 Platform 对账恢复。

### 3.5 `kairo-platform-server`

新增建议表：

- `script_capability_policy`：平台/应用范围、允许上限、revision、修改人；
- `script_session`：目标、档位、TTL、状态、脚本哈希和 Agent 结果；
- `script_session_event` 或复用统一审计事件记录状态变化。

新增服务负责计算最终档位、创建试用会话、下发命令、过期补偿和提升正式规则。所有状态变化使用
乐观锁和幂等键。

### 3.6 API 与 Web

建议公开：

- `GET/PUT /api/v1/apps/{appId}/script-policy`；
- `POST /api/v1/scripts/compile`；
- `POST /api/v1/script-sessions`；
- `POST /api/v1/script-sessions/{id}/validate`；
- `POST /api/v1/script-sessions/{id}/apply`；
- `POST /api/v1/script-sessions/{id}/promote`；
- `DELETE /api/v1/script-sessions/{id}`。

页面明确展示档位、真实权限、TTL、目标实例和不可安全强杀任意脚本的限制。

## 4. 实施顺序

1. 冻结能力档位和有效策略计算规则。
2. 重构 Groovy 策略和编译上下文，保持 SAFE 行为兼容。
3. 接入目标 ClassLoader 和弱引用编译缓存。
4. 配置化 RuleDispatcher，增加失败熔断和结构化指标。
5. 实现 Agent 本地 TTL 与 ScriptSession。
6. 增加 Platform 策略、数据库、命令和 API。
7. 完成 Web、审计、安全说明和真实 JVM 测试。

## 5. 测试方案

- SAFE 回归：现有安全绕过测试必须继续通过。
- EXTENDED：允许配置类可用，未配置敏感类被拒绝。
- UNRESTRICTED：IO、网络、反射、线程和业务依赖可执行。
- ClassLoader：业务 DTO 只对目标 ClassLoader 可见时仍能编译执行。
- 熔断：超时、连续异常、执行器饱和均 fail-open 并停用后续命中。
- TTL：Platform 在线、离线和会话客户端断开三种情况下均过期。
- 升级：旧规则无 profile 字段时自动按 SAFE 处理。
- 泄漏：反复创建/销毁业务 ClassLoader 后编译缓存不阻止回收。

## 6. 验收证据

- 三种档位的能力矩阵及自动化结果；
- 使用目标应用私有 DTO 的真实编译/执行用例；
- Platform 断开后的 TTL 自动卸载证据；
- 超时后 fail-open、熔断和未退出任务诊断证据；
- 旧 V1.0 规则兼容证据；
- API、审计和数据库迁移说明。

## 7. 完成判定

三种档位语义稳定，完整权限能够实际执行，任何档位的异常都不会因为 Kairo Advice 直接破坏原方法，
临时会话在控制面失联时仍能自动失效，即判定完成。
