# V1.1 验收记录

结论：**ACCEPTED**。验收基线为 `V1.1` 分支 `a53595b`。

## 契约与功能证据

- INPUT / PLANNED / APPLIED 快照、单调 revision、转换日志、预览、实际捕获、恢复均已实现；
- 正式转换与预览复用 `TransformationPlan`，预览不调用 JVM retransformation；
- 结构化 ASM 指令 Diff 为权威结果，Vineflower 1.12.0 提供两侧近似 Java Before/After；
- Agent 五类 HTTP API及 Platform 主动轮询式安全代理可公开使用；浏览器不接触 Agent URL/token；
- V35 只持久化元数据，class bytes、base64 与反编译源码不进入命令、审计或元数据数据库；
- Web 明确区分只读 PLANNED 与 JVM APPLIED，并在反编译失败时保留指令 Diff；
- shaded `kairo-agent-core-modern.jar` 已验证包含 Vineflower `Decompiler.class` 与版本资源。

## 验收场景

- 双 ClassLoader 同名类的 identity、revision、快照和恢复互不串用；
- 四阶段哈希：增强前、预览、JVM 实际、卸载后均有真实 bytes 与 SHA-256；
- Kairo 前后测试 Transformer 共存，INPUT/APPLIED 语义正确；
- 快照 TTL/LRU、并发 revision、诊断队列、大小限制、超时和清理均有测试；
- 外部 JDK `javap -c -p` 读取 APPLIED class，观察到的 `KairoBridge` 与 Kairo 指令 Diff 一致；
- Vineflower 覆盖普通类、增强字节码、非法 class、类名不匹配、异常、超时和队列饱和。
