# V1.3 技术改造方案：扩展增强位置

## 1. 目标与当前差距

当前 `KairoTransformer` 只对普通非 void/void 方法织入两套 Advice，`InvokePhase` 只有 `BEFORE`、
`RETURN`、`THROWS`。目标由类名、方法名和描述符表达，不能描述构造器、FINALLY 或方法内部调用点。

本版本建立统一 `EnhancementLocation` 模型，并实现构造器和调用点增强。V1.4 的多规则链必须直接复用
该模型，因此本版本不能为每一种位置创建互不兼容的独立规则系统。

## 2. 技术决策

### 2.1 统一位置模型

建议位置类型：

- `METHOD_ENTER`；
- `METHOD_RETURN`；
- `METHOD_THROW`；
- `METHOD_FINALLY`；
- `CONSTRUCTOR_AFTER_SUPER`；
- `CONSTRUCTOR_RETURN`；
- `CONSTRUCTOR_THROW`；
- `CALL_BEFORE`；
- `CALL_RETURN`；
- `CALL_THROW`。

`EnhancementTarget = MethodIdentity + EnhancementLocation`。调用点位置额外包含被调用 owner、name、
descriptor、invoke opcode、出现索引及可选 bytecode offset fingerprint。

### 2.2 调用点身份稳定性

绝对字节码 offset 在重新编译后不稳定，因此持久化身份使用：

`caller method + callee signature + opcode + occurrence index + surrounding instruction fingerprint`。

发布时重新解析。如果 fingerprint 不一致，状态为 `TARGET_DRIFTED`，不得悄悄增强新的位置。

### 2.3 转换实现

- 普通方法和构造器优先复用 Byte Buddy Advice。
- 调用点增强使用 Byte Buddy `MemberSubstitution`、`AsmVisitorWrapper` 或独立 ASM visitor；在技术原型后
  选择一种，不允许同时保留两套生产实现。
- 任何实现都必须生成 V1.1 的统一 `TransformationPlan` 和位置元数据。
- 不允许改变类结构，继续使用 `disableClassFormatChanges()`。

### 2.4 FINALLY 语义

FINALLY 规则观察前一阶段处理后的最终返回值或异常。它默认只观察和记录；若允许修改结果，必须明确
它是链中的最后阶段，并由 V1.4 统一处理优先级和冲突。

## 3. 模块改造

### 3.1 `kairo-api`

- 扩展 `InvokePhase` 或引入兼容的 `EnhancementPhase`，旧枚举值保持序列化兼容。
- 新增 `EnhancementLocation`、`CallSiteSelector`、`CallSiteIdentity`、`TargetMatchResult`。
- `MethodSelector` 继续兼容旧请求，新规则以 `EnhancementTarget` 为权威模型。
- 脚本上下文增加 caller、callee、call arguments、call result、call throwable 等按位置可用字段。

### 3.2 `kairo-core`

- 把 `InvocationState` 扩展为统一执行状态，明确原方法参数、当前参数、原结果和当前结果。
- `RuleDispatcher` 按位置执行，但暂不在本版本重新定义复杂多规则组合。
- `DecisionValidator` 增加构造器和调用点参数/返回值/异常类型校验。
- `ReentryGuard` 的 key 包含 enhancement target，避免调用点规则与方法规则互相误判重入。

### 3.3 `kairo-agent-core`

- `InstrumentationRegistry` 从方法集合升级为目标/位置集合。
- `MethodMatchers` 拆分为类型、方法、构造器和调用点匹配器。
- 将 `VoidMethodAdvice`、`ValueMethodAdvice` 收敛为少量共享 Bridge 协议，避免每个位置复制逻辑。
- 新增构造器 Advice，严格处理未初始化对象限制。
- 新增调用点扫描器，发布前只读列举候选位置。
- 新增调用点转换器和转换后 ASM 校验。
- 对 native、abstract、不可修改类和不支持 opcode 返回明确诊断。

### 3.4 `kairo-bootstrap-api`

现有 `KairoBridge.enter/exit` 需要版本化扩展，建议新增通用事件入口而不是破坏旧签名：

- `enterV2(InvocationEnvelope)`；
- `exitV2(token, OutcomeEnvelope)`；
- 或位置专用但共享 DTO 的构造器/调用点入口。

Bootstrap 层 DTO 必须极轻、无第三方依赖，并兼容旧 Agent 滚动升级。

### 3.5 `kairo-platform-server` 与 Web

- 规则目标 JSON 增加 location 和 call-site selector；旧规则迁移为现有三个方法阶段。
- 目标发现 API 返回构造器、特殊方法标记和调用点候选。
- 保存规则前执行目标解析和漂移校验。
- 页面按方法阶段、构造器、内部调用点分步选择，展示匹配数量和风险。
- Diff 页面直接定位到 V1.1 预览中的修改位置。

## 4. 实施顺序

1. 冻结 `EnhancementLocation`、脚本上下文和旧规则兼容映射。
2. 重构 registry、plan 和 Bridge，使普通方法先通过新模型回归。
3. 实现 FINALLY 并验证现有 BEFORE/RETURN/THROWS 无回归。
4. 实现构造器扫描、预览、增强和恢复。
5. 完成调用点只读扫描与稳定身份算法。
6. 选择单一调用点转换实现，完成参数、返回和异常路径。
7. 接入 Platform 数据、API、Web 和完整测试。

## 5. 测试矩阵

- 普通方法：static/private/final/synchronized/default interface/void/value。
- 构造器：默认构造、重载、`this()` 链、`super()`、构造异常。
- 调用指令：`invokevirtual`、`invokeinterface`、`invokestatic`、`invokespecial`；动态调用另列兼容范围。
- 调用点：重载方法、同一 callee 多次出现、嵌套 try/catch、调用异常。
- 校验：参数类型错误、primitive、void、checked exception、不可修改类。
- 漂移：重新编译导致调用点 fingerprint 改变时必须拒绝旧位置。
- 恢复：每个位置独立卸载后字节码与预期一致。

## 6. 验收证据

- 每一种承诺位置的 Before/After 字节码 Diff；
- 构造器 `this/super` 安全用例；
- 同一 callee 出现三次并精确选择第二处的用例；
- 调用点漂移拒绝用例；
- native/abstract 等提前拒绝用例；
- 旧 V1.0 规则无迁移操作即可继续运行的证据；
- 真实 JVM 增强和逐位置卸载结果。

## 7. 完成判定

所有位置通过统一目标、转换计划、Bridge 和预览模型运行；不存在仅由页面或特殊旁路维护的位置；
构造器和调用点能够准确增强并独立恢复，即判定完成。
