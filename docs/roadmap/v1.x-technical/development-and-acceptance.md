# V1.X 多智能体开发与验收规范

## 1. 角色

### 主验收智能体

- 维护冻结契约和技术方案；
- 审查版本设计偏差；
- 决定共享模型、协议和数据库冲突的处理方式；
- 执行阶段验收和跨版本集成验收；
- 不替开发智能体掩盖未完成项。

### 版本开发智能体

- 只负责分配版本或明确子任务；
- 开工前阅读本目录 README、对应版本方案及其前置版本方案；
- 在发现技术方案无法实施时先提交设计偏差说明，不自行改变公共语义；
- 提交实现、测试、文档和验收证据。

### 专项测试智能体

- 可独立负责兼容矩阵、性能、共存或 API 契约测试；
- 不以修改产品语义来让测试通过；
- 测试夹具与产品代码分离，失败结果必须可复现。

## 2. 开发波次

不建议六个版本同时编码。推荐：

| 波次 | 可并行工作 | 合入门槛 |
| --- | --- | --- |
| 0 | 冻结公共身份、revision、target、命令和错误契约 | 主验收智能体批准契约 |
| 1 | V1.1 主实现；V1.2/V1.3 技术原型；兼容测试基建 | V1.1 核心模型和转换 plan 合入 |
| 2 | V1.2 与 V1.3 正式实现并行 | 两版本分别通过验收，统一 target/loader 语义 |
| 3 | V1.4 核心；冲突分析、共存测试可拆分并行 | 规则链、fencing、精确卸载通过验收 |
| 4 | V1.5 与 V1.6 并行 | V1.4 底层语义冻结 |
| 5 | 跨版本回归，为 V1.7 LTS 提供输入 | 六个版本全部通过集成验收 |

## 3. 开工包

给开发智能体的任务必须包含：

- 对应技术方案文件路径；
- 允许修改的模块和禁止扩大范围的说明；
- 当前基线 commit；
- 前置契约版本；
- 必须运行的测试命令；
- 预期交付格式；
- 主验收智能体的评审检查点。

建议任务描述模板：

```text
实现 Kairo V1.X 的 <子任务>。
技术依据：<绝对路径或仓库相对路径>。
前置契约：<版本/hash>。
允许修改：<模块>。
不得修改：公共契约语义、无关版本功能。
交付：实现、迁移、测试、文档、风险、回滚和验收证据。
遇到方案冲突时停止扩大设计，提交偏差说明等待评审。
```

## 4. 评审检查点

每个版本至少经过四次检查：

### 检查点 A：设计映射

- 当前代码落点是否准确；
- 是否复用冻结契约；
- 是否引入重复模型或旁路；
- 数据迁移和兼容方案是否可行；
- 测试能否证明关键风险。

### 检查点 B：核心骨架

- 领域对象、协议 DTO、表结构和接口已经建立；
- 普通 V1.0 场景先通过新骨架回归；
- 尚未接 UI 前已有 Agent/服务级测试；
- 没有通过硬编码或全局 reset 掩盖问题。

### 检查点 C：功能完成

- 对应技术方案的主要工作全部实现；
- 异常、并发、重试、卸载和升级路径通过；
- API、审计、文档同步；
- 开发智能体提供完整证据。

### 检查点 D：集成验收

- 与所有前置版本联合运行；
- 数据库从旧版本升级；
- Agent/Platform 协议组合符合兼容矩阵；
- 性能和内存没有不可解释退化；
- 不存在 P0/P1 缺陷。

## 5. 验收结论

主验收智能体只能给出以下结论：

- `ACCEPTED`：全部门槛通过，可以作为后续版本基线；
- `ACCEPTED_WITH_FOLLOW_UP`：仅存在不影响后续契约的 P2/P3 项，已有负责人和期限；
- `CHANGES_REQUIRED`：存在可修复的功能、测试或设计缺口；
- `REJECTED`：实现偏离核心契约、引入不可接受旁路或无法安全升级。

结论必须引用测试、Diff、日志或文档证据，不能只写主观判断。

## 6. 通用检查清单

### 代码与架构

- 模块边界符合 `docs/architecture/module-boundary-governance.md`；
- Bootstrap API 无第三方重依赖；
- 业务请求线程不执行网络、反编译、数据库或类转换控制工作；
- Agent 缓存不无界增长、不无意强引用业务 ClassLoader；
- 不使用 `RESET_ALL` 代替精确卸载成功；
- 失败默认保持原业务行为，除非明确启用其他策略。

### 数据与协议

- Flyway 支持空库和已有库升级；
- 写操作有幂等和乐观锁；
- 协议字段有默认值和旧版本行为；
- 状态机转换是原子的、可审计的；
- 资源使用稳定 ID，展示名称不作为身份键。

### 测试与证据

- 单元测试覆盖纯模型；
- 独立 JVM 测试覆盖真实 Instrumentation；
- 端到端覆盖 Platform → command → Agent → JVM → ack；
- 卸载结果通过实际字节码或规范化结构验证；
- 并发、超时、重复、乱序和断线场景有测试；
- 文档中的验收标准逐项有证据。

### 安全与运维

- 高权限脚本和高风险增强完整审计；
- Token、脚本和 class bytes 不出现在无保护日志中；
- 临时操作有 TTL 和恢复路径；
- 错误返回包含可重试性和恢复建议；
- 运维能在 Platform 不可用时执行必要的 Agent 紧急停止。
